# QR Code Fix for We-Roster Mobile

## Issue
The QR code generated by `npm start` was not usable for connecting to the development server.

## Solution
Updated the Expo development server configuration to use tunnel mode by default, which generates a publicly accessible QR code that works across different networks.

## Changes Made

### 1. Updated package.json scripts
- Changed default `start` script to use `--tunnel` flag
- Added alternative start options:
  - `npm run start:lan` - Uses local network (original behavior)
  - `npm run start:localhost` - Uses localhost only
  - `npm start` - Uses tunnel mode (recommended for QR code)

### 2. Enhanced app.json configuration
- Added custom scheme: `we-roster-mobile`
- Added bundle identifier for iOS
- Added intent filters for Android deep linking
- Improved deep linking support

## Usage

### For QR Code Development (Recommended)
```bash
npm start
```
This will start the development server with tunnel mode, generating a QR code that works from any network.

### Alternative Options
```bash
# Use local network (if on same WiFi)
npm run start:lan

# Use localhost only (for local testing)
npm run start:localhost
```

## How It Works
- **Tunnel mode**: Uses ngrok to create a public URL that tunnels to your local development server
- **QR Code**: Contains the tunnel URL, making it accessible from any device with internet connection
- **Deep Linking**: Enhanced app configuration supports better deep linking for development builds

## Troubleshooting
If QR code still doesn't work:
1. Ensure you have internet connection
2. Try `npm run start:lan` if on same network as device
3. Check firewall settings
4. Verify Expo CLI is up to date: `npm install -g @expo/cli@latest`
